## Container feasibility (checked, not assumed)
- No `docker`, `podman`, `buildah` or `nerdctl` in the sandbox.
- `https://ghcr.io/v2/` and `https://registry-1.docker.io/v2/` both returned **403** from the sandbox.
- So sessions can write the `Dockerfile`, the smoke script and the workflow, but cannot build, push or test an image. GitHub Actions on the owner's fork does that. Every Phase 5 leaf is *written, NOT built or run* until the owner's leaf `5.b.ii.zi`.
- The SDK is a library, so the image is a runtime and base image bundling the built SDK, not a service. `yarn build` already produces a publishable `dist/` with its own `package.json`. The `prepare` hook runs the build only in a git-install context; the Dockerfile will install with `--ignore-scripts` and call `./scripts/build` itself.
- The registry host is spelled `ghcr.io`. Image name must be lowercase: `ghcr.io/zapier-codes/bandlab-sdk-typescript`.
- Fork caveats for the owner: Actions are disabled on forks until enabled; the first pushed package is private until visibility is changed; the `org.opencontainers.image.source` label links the package to the repo.
