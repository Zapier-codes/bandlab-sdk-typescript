## What was done
Wrote `docs/research/CAPTURE-GUIDE.md` (the first file in `docs/research/`), for the owner to record BandLab's own requests from their own account:
- **Rules:** own account only (a second account the owner also owns for anything needing two people); start recording *after* login so the password is never captured; a raw HAR holds tokens, cookies and the owner's email, so **never send or commit a raw HAR**; destructive items on a throwaway only; no payment screens; one action per capture; terms-of-service caveat (not checked).
- **Three methods, with honest limits:** (A) desktop browser DevTools, recommended; (B) phone browser through a capture tool, website features only; (C) the BandLab phone app, flagged as often not possible (user certificates are usually refused; the guide says not to root or patch the phone and to report "app traffic not capturable").
- **HAR export steps** for Chrome/Edge, Firefox and Safari, plus a 10-second check that a capture actually contains the method, full URL, request body, JSON response and a 2xx status.
- **P0, the base host:** a two-minute check (no HAR needed) of which API host the BandLab site calls and whether `test.bandlab.com` appears at all. This answers the open base-URL question from `1.a.i.zo`.
- **One capture task per register item, G01 to G14**, each with what to do, what to look for (using the leads recorded in `COVERAGE.md`: `me.update` has an `email` field, `revisions.create` takes a `song`, the `Revision` type already has `tracks`/`auxChannels.effects`), and safety notes. "The app has no such action" is explicitly a valid result.
