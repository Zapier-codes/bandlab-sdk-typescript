## What was done
- **`scripts/research/scrub-har.py`** (standard library only, written to be Python 3.8-compatible; run on 3.12 here). Two modes:
  - *Scrub:* writes a separate file (never modifies the input; refuses to overwrite without `--force`); keeps only known HAR fields; drops credential headers and all cookies; keeps other header **names** but redacts their values (except `content-type`, `accept`, `content-length`); drops static assets, OPTIONS preflights and URL fragments; keeps JSON and URL-encoded form bodies and omits every other body; redacts the **values** of sensitive keys (keeping key names, and keeping booleans and numbers so `hasPassword: true` stays a boolean); replaces owner identifiers, every email, JWTs, bearer tokens, UUIDs and long hex ids with stable placeholders (`UUID-0001`, `HEX-0001`, `EMAIL-0001`, `OWNER-EMAIL`, `OWNER-USERNAME`, `OWNER-NAME`); shortens long JSON arrays to 5 items with a note. Then it runs its own check on the output and **deletes the output if the check fails**.
  - *`--check FILE`:* a structured leak check (credential headers, cookies, header values, sensitive keys with real values, emails, JWTs, bearer tokens, UUIDs, long hex ids, credentials or fragments or secret query values in URLs, binary or non-JSON bodies, static or preflight entries, owner identifiers). It reports the kind of problem and its location and **never prints the secret value**.
- **`scripts/research/fixtures/synthetic-capture.har`**: 14 entries containing only fake secrets (fake bearer token, cookies, JWT, emails, username, UUIDs, hex id, a form with a password, multipart upload, HTML with embedded state, a redirect with a token, credentials in a URL, an image, a script, a preflight).
- **`scripts/research/test_scrub_har.py`**: 24 `unittest` tests, including 21 planted-leak cases for the checker, odd HAR shapes, and the failure path.

## Defects found and fixed while building (all caught before commit)
1. `raise SystemExit("message")` exits with code 1, but the contract is 2 for bad input; fixed with a `die()` helper.
2. A URL with credentials (`https://user:pw@host/ping`) became `https://EMAIL-0002/ping`: the email pattern swallowed the host. Credentials are now removed from the URL entirely.
3. Scrubbing an already scrubbed file lost its "body omitted" and "arrays shortened" notes. Notes are now carried through, and a test asserts a second pass changes nothing.
4. A `:path` header kept `token=zzz`. All URL-like headers now go through the URL scrubber.
5. The **checker never looked inside the query string of `request.url`**, so a leaked `&token=...` would have passed. It now checks URLs, redirect URLs and URL-like headers, and flags fragments.
6. In an early version of my own verification I trusted a passing check; looking at the actual output entry by entry is what found items 2 and 4.

## Decisions made (owner may overrule)
- Header **names** are kept (with values redacted) because which headers the app sends is evidence (for example an `X-Client-Id`); credential-named headers are dropped entirely.
- Booleans and numbers under a sensitive key are kept (they carry shape, not secrets); strings, objects and arrays are redacted.
- Usernames and names are replaced as **substrings**, case-insensitively, and must be at least 3 characters. A short or common word as a username will over-redact.
- OPTIONS preflights are dropped as noise.
- Only the documented place for raw files is git-ignored: `docs/research/raw/` and `*.raw.har`.

## Known limits (stated to the owner in `HAND-BACK.md`)
- Best effort, not proof. It cannot recognise a secret it has no rule for: a numeric PIN under an unusual key, a name or phone number typed into a free-text field, numeric ids (only UUIDs and 24+ character hex ids are replaced).
- **Never run on a real browser HAR**: none exists yet. The fixture is synthetic and my odd-shape probe is hand-made. The first real capture should be eyeballed after scrubbing.
- Not run on Termux or on Python 3.8; run on Python 3.12 only.
- Arrays are shortened to 5 items, so a longer array's tail shape is lost (the note says so).
