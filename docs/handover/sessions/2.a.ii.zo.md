## What was done
- **`scripts/research/har-to-endpoints.py`** (standard library only, Python 3.8-compatible; run on 3.12). Reads scrubbed `.har` files (default: `docs/research/captures/`) and writes `docs/research/endpoints/<domain>.json`, one file per domain that has endpoints. Per endpoint it records: method, host, API version prefix (`/api/v1.3`), path template (`UUID-`/`HEX-` ids and numeric segments become `{id}`; `{email}`, `{username}` likewise), query **keys**, header **names**, status codes, how many samples and which capture files (and G-items, from the file-name prefix) it came from, and the **shape** of JSON and form bodies: **types only, never values**, merged across every capture of the same endpoint. Keys present in only some samples end in `?`; `null` merges become unions such as `email|null`; ids show as `uuid` or `hex-id`; redacted values show as `redacted`.
- **Flags what the SDK lacks:** each endpoint is compared (verb plus path template, parameter names ignored) with the SDK table in `docs/endpoint-status.md` and marked `inSdk` with its `sdkCall`, or flagged **NOT in the SDK** in the printed summary.
- **Domain files** use the plan's names plus one addition: `messaging.json` (the original plan's endpoint list had no messaging file, but G01 needs one). The last recognised path segment decides the domain; anything else goes to `unknown.json`.
- **Safety:** every input is run through the scrubber's own leak check first. **If any file fails, all are refused and nothing is written** (exit 1); failures print the kind and location of the problem, never the value. There is deliberately no override.
- `--dry-run` prints the summary and writes nothing; `--out`, `--status-file` and file or directory inputs are accepted.
- **Fixture:** the existing synthetic fixture is reused. The tests scrub it into a temporary captures folder and add a second, altered capture to test merging. (No new static fixture file was needed.)
- **Docs:** `HAND-BACK.md` (layout line, new "Extraction" paragraph) and `CAPTURE-GUIDE.md` now describe the extractor as built.

## Decisions made (owner may overrule)
- **Types only, no example values.** It is the safest default, but it loses enum values (for example a `status` that is `"processing"` or `"done"`), which Phase 4's typing leaf may want. If so, add an opt-in `--examples N` later; do not make it the default.
- The extractor **refuses unscrubbed input outright** instead of warning.
- Domain mapping is a heuristic on path segments, only a grouping aid for humans; the real classification happens in triage.
- Stale domain files from earlier runs are not deleted when a later run no longer produces that domain. The output is a regenerated view of the whole captures folder, so re-run it over everything.

## Known limits
- Only as good as the scrubbed captures. Path segments that are not UUIDs, long hex ids or digits (slugs, names) are not templated, so they will appear as false "NOT in the SDK" entries; triage must look over that list by hand.
- It compares **endpoints only** (verb plus path). It does not compare query parameters, request bodies or response shapes with the SDK's types; that is later work (Phase 3 `zi` leaves and `4.a.i.zi`).
- Arrays are shortened to 5 items by the scrubber, so the shape reflects at most those items.
- With a single sample no key can be marked optional.
