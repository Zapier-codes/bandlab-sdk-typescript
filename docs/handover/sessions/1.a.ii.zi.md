## What was done
- `scripts/utils/coverage-report.cjs`: dependency-free CommonJS (like its neighbours in `scripts/utils`). Parses every `<code title="verb /path">client.<accessor>.<a href="file">method</a>` line of `api.md` into a row (verb, path, accessor, method, source file), then diffs (verb, path, accessor) against `docs/handover/endpoint-inventory.tsv` as a multiset, so a duplicated row counts as drift too.
- `scripts/coverage`: three-line bash wrapper in the repo's script style (`cd` to the repo root, then `node scripts/utils/coverage-report.cjs "$@"`), executable.
- Options: `--api <file>`, `--inventory <file>` (for testing and for later leaves), `--tsv` (prints the parsed rows as `verb  path  accessor  method  file`, sorted like the inventory, no diff), `-h`.
- Exit codes: **0** no drift, **1** drift (prints `+` and `-` lines), **2** an input could not be read or parsed (also if any endpoint-looking line in `api.md` fails to parse, so a format change cannot silently shrink the count).
- The inventory has no method names (its third column is the accessor with a trailing dot), so the diff key is those three columns; `--tsv` is where method names and files come from. Rows that exist only in the inventory print `client.<accessor>*`.
- `package.json` was not touched (no `yarn coverage` alias, to avoid confusion with jest's coverage).

## Decisions made
- Kept the inventory as the immutable baseline snapshot rather than regenerating it. The report tells you when `api.md` drifts from it; deciding whether the drift is intended and refreshing the snapshot is a human step.
- Added `--tsv` now because parsing already produces those fields and `1.a.ii.zo` needs them; no extra parsing logic.
